## Answer

**Structural decision (needed to make this ticket buildable at all):** the ROM is prose Markdown per ticket 07's contract — not something `report` should re-parse to recover numerator/denominator/conformidade. Extended `measure` (ticket 03) to also write a `<indicator.id>.json` structured summary next to each `.md` ROM (`rom/summary.py`'s new `IndicatorSummary`/`summarize()`, flattening any shape's `CalculationResult` into a shape-agnostic row: numerator/denominator pooled appropriately per shape — straight from `memoria` for `ratio`, summed across categories for `segmented_ratio`, QCSI/QRC for `count_difference`, `None`/`None` for `external_catalog_sum` since it's a point sum, not a ratio). `report` reads these JSON sidecars, never the Markdown.

- `pyauditor/excel/groups.py` — **scope note, not a full implementation of docs/spreadsheet.md's group model:** the doc lists several indicators under more than one group tab (e.g. INMS 1.1 appears in `ATENDIMENTO_N1`, `ATENDIMENTO_N2`, *and* `OPERACAO_N3`), envisioning one measurement *per group* for shared services. The engine doesn't support that — one YAML+CSV per contractual indicator number means one measurement, full stop (tickets 02-07). `primary_group()` places each indicator on the *first*-listed tab (N1 → NOC/SOC → N2 → N3 order) rather than duplicating a single measurement across multiple tabs or fabricating per-group breakdowns that don't exist. INMS 1.8 isn't on any group tab in the source doc at all (Anexo E's point sum is separate), so it appears only in `INMS_BASE`.
- `pyauditor/excel/report.py` — `build_report_workbook()` builds `INMS_BASE` (all 26 columns from spec §Aba 4, in order; derivable ones filled — competência, grupo operacional, código INMS, descrição, órgão, meta, sentido, numerador, denominador, resultado, unidade [derived per-shape: `%`/`unidades`/`pontos`], conformidade, diferença para a meta; fiscal-manual-only and ticket-10/GLOSAS columns left `None`, not fabricated) plus the 4 group tabs (`ATENDIMENTO_N1`, `MONITORAMENTO_NOC_SOC`, `ATENDIMENTO_N2`, `OPERACAO_N3`), each with a simplified 7-column table (código, descrição, órgão, resultado, meta, conformidade, penalidade) rather than the doc's full MinC/MTur/Consolidado block structure — that block depends on the MinC/MTur segregation ticket 10 already flagged as fog, so building it now would mean fabricating a consolidation formula against data that doesn't exist. Rows sorted by `contractual_id` for determinism. `build_report_workbook` is pure (in-memory); `build_report` adds the file write.
- `pyauditor/excel/_style.py` (new) — shared cell styles (Arial 10 body, bold dark-fill headers, thin borders, no decorative fills, per `docs/styleguide.md`) factored out of `capa.py` so `report.py` doesn't duplicate them; `capa.py` refactored to use it too.
- `pyauditor/cli/report.py` — `run_report(competencia, capa_path, roms_dir, output_path)`: fails clearly (exit 1, explicit message pointing at `bootstrap`) if the capa doesn't exist; fails clearly if `<roms_dir>/<competencia>/` doesn't exist or has no `.json` sidecars (pointing at `measure`); otherwise loads every summary and calls `build_report`. Rerunning for the same competência is non-cumulative by construction — `build_report_workbook` always builds a fresh workbook from whatever `.json` files currently exist on disk, never reads/appends to a prior output file.
- `pyauditor/cli/main.py` — wired the real `report` subcommand (was a stub) with `competencia` positional + `--capa-path`/`--roms-dir`/`--output-dir`, building `<output-dir>/relatorio_<competencia>.xlsx`.

Verified: `uv run mypy --strict src tests` → `Success: no issues found in 46 source files`. `uv run pytest -q` → `75 passed`. Ran the full `bootstrap → measure → report` pipeline via the installed CLI against all 14 real fixture configs: `INMS_BASE` got all 14 rows (including INMS 1.8 with a blank grupo operacional), `ATENDIMENTO_N1` correctly held only its 7 indicators with real computed results (e.g. INMS 1.1: 97.71%, não conforme, 222.14 pontos; INMS 1.11: 18.9%, não conforme, 695.12 pontos), matching every other ticket's independently-verified numbers exactly.
