# 06 — Criar workflow de CI de qualidade

**Type:** grilling
**Status:** resolvido
**Blocked by:** 03, 04

## Question

Criar um workflow que rode a qualidade do repo — `ty` + `ruff` (+ `pytest` + coverage, alinhado aos gates já existentes) — como trabalho que passa no push/PR, sem tocar nos workflows de deploy existentes (docs.yml, static.yml).

Decisões:

-   **Trigger**: push em `main`/`master`? PR? ambos? qual `runs-on`.
-   **Setup**: `actions/checkout`, `astral-sh/setup-uv` (padrão uv), Python 3.12.
-   **Steps**: `uv sync` (com grupo dev), `uv run ty`, `uv run ruff check .`, `uv run pytest` (com gate de coverage que o pyproject já define).
-   **ty estrito como gate**: o `error-on-warning` default do ty faz warning falhar — manter (é o "strict do ty" decidido)?
-   **Versão do ty**: pinar (ex.: `ty@0.0.73` num `uvx` step) ou seguir `uv`/tool global? Registrar a decisão.

## Resolução

Workflow criado: `.github/workflows/quality.yml` ("Quality gates"). Decisões:

-   **Trigger**: **push em `main`/`master` + PR** (decisão do human nesta sessão) — gate de qualidade roda em toda PR (onde a cobrança acontece) e protege a branch principal. `runs-on: ubuntu-latest` (padrão do repo), `timeout-minutes: 30`.
-   **Setup**: `actions/checkout@v5` + `astral-sh/setup-uv@v6` (`enable-cache: true`) + `actions/setup-python@v6` Python 3.12 — espelha o `weekly-testing.yml` existente.
-   **Steps**: `uv lock --check` → `uv sync --locked --group dev` → Ruff (`ruff check src tests` + `ruff format --check src tests`) → **`uvx ty@0.0.73 check src tests`** → `uv run --locked pytest` (o pyproject já liga `--cov` branch e `fail_under = 85` via addopts/coverage — gate de coverage herdado, sem flags extras).
-   **ty estrito como gate**: **mantido** — `terminal.error-on-warning = true` default faz warning falhar; é o "strict do ty" decidido no ticket 03. Sem overrides.
-   **Versão do ty**: **pinada** em `ty@0.0.73` via `uvx` — o ty é tool global do repo (Q1/A), **não** é dependência do projeto; logo `uv run ty` não o acha num runner limpo (não está no `.venv` nem no PATH do CI). `uvx ty@0.0.73` pinada na versão que mediu o baseline do ticket 02. Registrado em comentário no próprio workflow.
-   `permissions: contents: read` (mínimo); `concurrency` com `cancel-in-progress: true`; nada de deploy — docs.yml/static.yml intocados.
-   **Bug latente corrigido**: o `weekly-testing.yml` (workflow existente, não-deploy) rodava `uv run --locked ty check` — no CI isso falharia porque o ty não está no `.venv` do projeto nem no PATH. O passo foi trocado para `uvx ty@0.0.73 check src tests` (mesma resolução pinada), com comentário explicando.

Validado localmente: YAML dos workflows parseado; `uvx ty@0.0.73 check src tests` → All checks passed; `uv run ruff check src tests` / `format --check` → ok; `uv run pytest` → 559 passed / 34 skipped / 89.29% branch.
