**Type:** task

## Question

Atualizar os documentos "vivos" que nomeiam basedpyright/mypy como ferramenta do projeto, na terminologia do ty (decisão Q2/a + F2/b). Sem criar ADR novo (Q6/b).

-   `CODING_STANDARDS.md`: seção "Stack", linhas com basedpyright → ty (com `# ty: ignore`), comandos da seção "Antes de declarar tarefa concluída" (`uv run ty ...`).
-   `README.md`: linhas 51, 210, 216 (strict-mode ↔ ty-strict) e comandos `uv run basedpyright` → `uv run ty`.
-   `pyguide.md`: reescrever as seções de type-checking e suppression (§ type checking, § suppress) para `[tool.ty.rules]` e `# ty: ignore[<rule>]`; manter a estrutura do guia.
-   `.gitignore`: `.basedpyright/` → `.ty/`? (verificar se o ty cria cache de dir e qual nome — se não criar, remover a linha).
-   Regra de histórico: docs/adr/0003 e docs/spec/inms-pipeline.md **não são alterados** (registro de época). Confirmar no diff.
-   Checar se as edições quebram o build do zensical (docs site) — se sim, `zensical build --clean` sanitiza e verificar.

## Resolução

Arquivos tocados:

-   `CODING_STANDARDS.md`: seção "Stack" reescrita para **ty** (strict por default; `[tool.ty]` no pyproject); linha "Ruff, basedpyright" → "Ruff, ty"; comando da lista "Antes de declarar tarefa concluída" `uv run basedpyright` → `uv run ty check`.
-   `README.md`: linha 51 (`basedpyright` → `ty`), linha 210 (`uv run basedpyright` → `uv run ty check`), linhas 216–218 (strict-mode ↔ ty-strict: "default do ty é mais estrito que o basedpyright strict").
-   `pyguide.md`: §2.21 reescrita — "Type-check the code at build time with ty (strict by default; see `[tool.ty]`…)" e link https://docs.basedpyright.com/ → https://docs.astral.sh/ty/ (2 sites); §3.19.7 Ignoring Types reescrita — contrato `# ty: ignore[<rule>]`, `respect-type-ignore-comments = false` torna o `# type: ignore[...]` legado comentário comum (exemplo migrado para `# ty: ignore[invalid-assignment]`). Estrutura do guia mantida; idioma do guia (inglês) preservado.
-   `.gitignore`: linha `.basedpyright/` **removida** — o ty não cria diretório de cache no repo (fato do ticket 02), nada a adicionar.
-   `.vscode/settings.json`: decisão Q4/a formalizada — `python.analysis.languageServerMode: full` (Pylance) → `python.languageServer: none` (Pylance desligado; o type-checking fica com a extensão oficial `astral-sh.ty`). Recomendação da extensão registrada em `.vscode/extensions.json` novo (`"recommendations": ["astral-sh.ty"]`).
-   Histórico preservado no diff: `docs/adr/0003-*` e `docs/spec/inms-pipeline.md` intocados (registro de época). Menções restantes a basedpyright nas docs vivas são comparativas ("mais estrito que o basedpyright strict"; "legacy `# type: ignore`"), não ancoram a ferramenta.

Gates: `uvx ty@0.0.73 check src tests` → All checks passed; `uv run ruff check src tests` → All checks passed; `uv run ruff format --check src tests` → ok; `uv run pytest` → 559 passed / 34 skipped / 89.29% branch (>= 85). Zensical: `docs_dir = "portal"` (zensical.toml) e nenhum arquivo tocado vive sob `portal/` — o build do site não é afetado; grep em `portal/**` sem menções a basedpyright/mypy/`type: ignore`.
